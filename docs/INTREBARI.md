# Open questions and conservative choices (stages 1–2)

Written while building; each item states what was assumed. Confirm or correct with Zoltan.

1. **Machine "Conform Extruder"** (type Sector / extrudare) is seeded on the owner's instruction (2026-09-29); it is what extruded Al measurements use.
2. **Class 5 has no shape on paper, but `constructions.shape_id` is NOT NULL.** Added shape `LITA` ("Liță clasa 5") so the class 5 seed loads. Sârmă rows with several shapes (e.g. RM + SM72 + SM120) are stored once with the first shape as `shape_id` and all shapes in `constructions.data.forme`; stage 2 may split them.
3. **Extra schema (migration 001):** `constructions.active` (deactivate inside a draft; not copied to the next revision), `login_attempts` (5 failures / 15 min lockout per username), `seed_warnings` (the items of `seed/verificare_seed.json`, shown on the draft revision). See `docs/DATA-MODEL.md`.
4. **Required inputs.** Diameter (two readings, or Î and L for sector) and sample mass are required; measured resistance is optional (if a value is typed, temperature is required). Operator and client are optional (the operators list starts empty and Personal cannot edit lists); sample type is required.
5. **One open revision per document.** "Revizie nouă" is refused while a draft or an in-verification revision exists.
6. **Who may edit a draft.** Only its elaborator (an Inginer). The seeded drafts have no elaborator: the first Inginer who edits or submits one becomes the elaborator (so the other Inginer can verify).
7. **Rejection** is done by the verifying Inginer (not the author) and needs a reason; the revision returns to `ciorna`.
8. **Correction keeps the record's own revision, shift and crew** and its construction; machine, operator, client, sample type, values and notes can change. Personal: only records they created (any version), only while the current shift equals the record's shift.
9. **IEC checks at submit and again at activation.** Blocking: class 2 wire count below the Tab. 4 minimum for the shape group (RM circular, RMC compacted, SM* shaped); class 1 Al 10–35 mm² as sector (Tab. 3 note a); class 5 wire Ø above Tab. 5; min ≥ max in a limit; no active construction. All IEC ones become warnings when `iec_exception_reason` is set. Warning only: section missing from the IEC table; mass not within 0.85–1.15 × (wires × wire mass) — the tolerance is a guess, please give the real rule.
10. **RM is checked against the compacted minimum** (owner, 2026-09-29: Al 50 RM has min 6 wires). Seed shape RM has `iec_group = compactat`; a shape with group `circular` still needs 19 wires at 50 mm². This supersedes acceptance case 23 of `docs/ETAPA-1.md` (7-wire RM Al 50 blocked): the seeded Al draft now passes the IEC checks. 54.6 RM has no IEC row (warning).
11. **"Today" on the home page** = records created today plus the current shift's records (so the night shift after midnight is complete). "Last 24 h" compares stored local timestamps as text; it can be off by one hour on the two daylight-saving switch days.
12. **Crew start dates** are seeded from the first-start date (A = today, B = +4, C = +8). The Administrator/Inginer must set the real cycle start in Date de bază → Schimburi.
13. **Node 22 and `node --test app/test`:** Node 22 does not accept a bare directory; use `npm test` or `node --test "app/test/*.test.js"`.
14. **Windows scripts are untested** (developed on Linux). `start.bat`, `instalare-serviciu.bat/.ps1` (Scheduled Task as SYSTEM, restart on failure, log in `data\server.log`) must be tried on a clean Windows machine.
15. **Stage 2:** default machines `TREFILARE 1` and `TREFILARE MF 1` are seeded (placeholder names, owner request 2026-09-29). Class V wire has only a nominal Ø on paper: verdicts stay `nedeterminat` until min/max are entered. Which wire rows should get measured resistance beyond Cu unifilar RE? Should class V wire also record the "Ø sârmă în liță" as a second reference?
16. **Browsers: Chrome, Edge and Firefox are used equally** (owner, 2026-09-29). Page numbers therefore do not use CSS page margin boxes (Firefox lacks them); `app/public/print-paginate.js` measures the content and builds numbered A4 pages in every browser. Verified in headless Chromium (`node tools/print-check.js`: PDF page count = numbered pages); **Firefox and Edge could not be tried in the dev environment** — please print one sheet from each on a factory PC. Without JavaScript the sheet still prints, with header/footer repeated but no page number.
17. **Stage 3:** flexible class 5 — the mass of the liță is "approximate" on the sheet, so it is shown without a verdict; measured resistance on the suviță is not offered. The toron resistance is compared with the finished conductor's Tab. 5 limit for its section (uncoated Cu, as in the seed). Should a coated (cositorit) variant exist, the sheet row needs the coated flag.
18. **Capability:** Cp/Cpk use the sample standard deviation (n − 1) on all values in the filter, not on rational subgroups, and the limits of the most recent revision in the selection. Please confirm this matches the factory's practice (e.g. minimum sample size, Ppk vs Cpk naming).
19. **Extra consumption** counts only mass above the maximum (as in the spec), not the deviation from the nominal.
20. **Finished-cable catalogue is a proposal.** Test names, units, categories and the compound each applies to (PVC / XLPE-EPR / HFFR) come from general practice, without clause numbers: please review `Date de bază → Tipuri de încercări`, fill the *Referință standard* per test (IEC 60502-1 / HD 603 / VDE 0276-603 clause) and deactivate what you do not use. The HFFR tests (halogen acid gas, acidity / conductivity, smoke density, bunched flame, oxygen index) are marked *externally performed* — change it when you get the equipment.
21. **Thickness requirements.** A test with readings gives average, minimum and maximum; the sheet holds a limit for each (e.g. average ≥ nominal, minimum ≥ 90 % nominal − 0.1 mm as your standard defines). The app does not compute that rule from a nominal: type the resulting numbers per design. Tell me if you want it computed from the nominal thickness.
22. **Conductor resistance of a finished cable** uses the design's conductor class (1, 2 or 5) and section for the IEC 60228 limit, or the sheet's own R max. No conversion for stranding or for the length of the drum is done: type the value in Ω/km or Ω on the sample length (default 5 m).
23. **Required tests per design** are chosen explicitly on the design (checklist); routine tests are expected on every drum, sample tests once per batch. Type tests are never required for a batch.
24. **Certificates are in Romanian only**, unsigned (blank signature line, no digital signature); is an English or bilingual version needed for customers? Also: should a certificate be issued only for a *closed* batch?
25. **Type tests** attach to a cable design (all revisions of the same design key together); there is no expiry or "valid until" yet.
26. **SPC:** control limits use the moving-range estimate of σ (individuals chart); subgroup X̄-R charts are not built. Alerts on the home page consider the last 3 days of products and up to 100 values each.
27. **Languages (2026-09-30).** Romanian and English are built; Hungarian is deferred (owner). Each user picks the language from the RO | EN buttons in the header; it is stored on the account (`users.language`) and the login page remembers the last choice in a cookie. Romanian is the master dictionary (`app/i18n/ro.js`); English is in `app/i18n/en/*.js` and a test fails when a key or a `{placeholder}` differs. A missing text falls back to Romanian. **Stored data stays as entered (Romanian):** sheet titles, machine and shape names, sample types, the finished-cable test catalogue. Decimal numbers keep the comma in both languages. The English wording is a first draft: please have someone at the plant read it (terms agreed 2026-09-30: fișă tehnică = data sheet, suviță = wire (of a multi-wire conductor), toron = strand, liță = bunched conductor; the Romanian menu “Nomenclatoare” is now “Date de bază”, English “Master data”). Open: should printed sheets and certificates take the language of the viewer, or be chosen per document when printing (customers)?
